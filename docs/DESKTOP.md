# デスクトップ版（2026-10-07）

ユーザーの「デスクトップのアプリを開くだけで全部起動し、閉じたら全部終了する」という依頼に対応した。

## 使い方

デスクトップの「Local Desk」をダブルクリックする。専用ウィンドウで準備状況を表示し、最後に選んだモデルを読み込み、チャット画面を開く。設定でBonsai / Qwen / Ornithを切り替えられる。終了はウィンドウ右上の×。

アプリが用意したAI・HTTPサーバー・WebView2を終了する。履歴・設定・バックアップと、専用ウィンドウの下書きは次回用に残す。他のアプリを一括終了する処理はない。

## 構成

- `Install-Desktop.ps1`：プロジェクト内の`.runtime/desktop/`にPython環境を用意し、pywebview 6.2.1をインストール。Windowsが返す実際のDesktopフォルダーにショートカットを置く。OneDriveで移動されたDesktopにも対応する。
- ショートカット：`pythonw.exe desktop.py`を実行する。ターミナルを表示しない。アイコンは既存のLocal DeskのSVGロゴと同じ図形で作成したICO。
- `desktop.py`：WebView2の専用ウィンドウ、モデル準備スレッド、アプリのHTTPサーバーを管理する。モデル準備後にアプリを表示し、生成中や読み込み途中の終了にも対応する。
- `engines.py`：デスクトップ用モードでは3モデルともPrismMLの専用llama.cppを使う。ポート1235でループバック・認証付きの推論を提供する。Qwen / Ornithの既存GGUFをそのまま読み込み、LM Studioのプロセスを起動しない。
- 終了時：生成をキャンセルし、所有する推論プロセスを停止。起動処理やモデル切り替えの完了を待ち、HTTPサーバーを閉じる。終了要求後のモデル起動を拒否する。
- Windowsの名前付きMutexで二重起動を防止する。終了処理完了まで保持し、再起動が旧プロセスと競合することを防ぐ。
- Windows Job Objectで専用プロセスの子を管理し、所有プロセスが終了すると子プロセスも終了する設定を適用する。

pywebviewのJS APIは公開しない。ブラウザ版のHost・Origin・トークン確認をそのまま使う。ブラウザの保存領域は`.data/webview/`に分離し、永続化する。ブラウザ版との会話履歴の保存先は共通だが、下書きはブラウザごとの保存先となる。

公式の[インストール手順](https://pywebview.flowrl.com/guide/installation)と[ウィンドウ・イベントAPI](https://pywebview.flowrl.com/api/)を確認した。デスクトップ版はWindowsでのみ検証済み。

## 実機検証

- 専用エンジンでQwen / Ornith / Bonsaiを順に起動し、それぞれ日本語の応答を取得。最後の終了でポート1235の解放を確認。
- 実際のWebView2ウィンドウとBonsaiで起動完了後の終了を実行。ウィンドウ終了後、アプリのテスト用ポート8766と推論ポート1235の両方が閉じ、テストプロセスも終了した。
- モデル準備開始から0.2秒後に終了するテストでも、起動完了後に画面を開く処理を実行せず、両ポートの解放とプロセス終了を確認。
- 同じ保存先のMutexをもう一度作ると、二重起動を判定できることを確認。
- Python 3.12.14 / 3.14.4の両方で26テスト中25件成功、1件スキップ。スキップはWindowsのシンボリックリンク権限。新しい4件は起動中の終了、生成のキャンセル、終了要求後の起動拒否、共通の推論先でのモデル識別。
- デスクトップの実ショートカットから通常版を起動し、`DESKTOP_READY`と画面のHTTP応答をログで確認。

アプリのログは`.data/desktop.log`、専用AIのログは`.data/engine-server.log`。公開ZIPから`.data/`と`.runtime/`を除外する。
